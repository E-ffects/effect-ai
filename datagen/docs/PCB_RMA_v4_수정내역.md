# PCB RMA v4 · 수정 내역 (품질 손실 금액 추가, 원인 후보 용어 정리)

- 작성: 2026-11-18
- 기준: v3 (`PCB_RMA_v3_수정내역.md`)에 두 단계를 추가
  1. **손실 금액:** 요구사항서 FR-03의 품질 조치 우선순위 점수(비즈니스 영향도) 중 **손실 금액이 30%** 인데, v3에는 비용 데이터가 없었다.
  2. **용어:** 교수님 피드백에 따라 화면·발표·데이터에서 쓰던 이전 용어를 **"원인 후보(cause candidate)"** 로 통일했다.

## 용어 정리: 원인 후보
원인 후보는 **제시 → 검토 → 채택(확정 원인이 됨) 또는 기각**의 단계를 거친다. AI가 내는 결과도, QA가 조사 중 검토한 것도 모두 "원인 후보"이고, 상태와 출처로 구분한다.

v3에서 v4로 이름이 바뀐 것 (v3 스키마로 적재한 경우 이 표대로 바꾼다):

| v3 | v4 |
|---|---|
| 테이블 `cause_hypothesis` | **`cause_candidate`** |
| `hypothesis_id` (HYP-…) | `candidate_id` (CAN-…) |
| `hypothesis_no` | `candidate_no` |
| `hypothesis_text` | `review_note` (문장의 "○○ 가설:"은 "○○ 검토:"로) |
| `verification_method` | `review_method` |
| `evidence_ids_json` | `review_evidence_ids_json` |
| `result` (SUPPORTED / REJECTED) | `review_status` (**ADOPTED** / REJECTED) |
| `decided_at` | `reviewed_at` |

화면·발표 용어:
| 데이터 | 표현 |
|---|---|
| AI 원인분석 결과 | 원인 후보 (출처 AI, 상태 제시) |
| `cause_candidate` | 원인 후보 (출처 QA 검토, 상태 채택·기각) |
| `review_note` / `review_method` / `review_evidence_ids_json` | 검토 내용 / 검토 방법 / 검토 근거 |
| `cause_assessment` CONFIRMED | 확정 원인 |
| `cause_assessment` PROBABLE | 추정 원인 ("원인 후보"와 섞이지 않게 구분) |

데이터·CSV·manifest에는 이전 용어가 남아 있지 않다. 생성 스크립트(`generate_v30.py`, `patch_v31.py`)는 이전 이름으로 먼저 만든 뒤 `patch_v4_terms.py`가 바꾼다.

## 설계: COPQ(품질 실패 비용) 틀
손실을 비용이 생긴 사건 하나하나로 기록한다. 금액 = **데이터의 실제 수량 × 가정 단가**이며, 모든 가정 단가는 `cost_rule` 한 곳에 근거와 함께 모았다. 단가를 바꾸고 다시 실행하면 전체가 다시 계산된다.

| 분류 | 비용 항목 | 수량 (데이터) | 단가 (가정) | 기록 시각 |
|---|---|---|---|---|
| 외부 실패 | REPLACEMENT_BOARDS 교체 기판 | 교체 출하 기판 수 (`service_action`) | 기판 원가 | 실행 시각 |
| 외부 실패 | CREDIT_REFUND 환불(크레딧) | 크레딧 기판 수 | 판매가 | 실행 시각 |
| 외부 실패 | **CUSTOMER_CHARGEBACK 고객 측 손실 청구** | 불량 수량 × **발견 단계 배수** | 판매가, 산업별 배상 상한 | 원인 적용 시각 |
| 외부 실패 | SORTING_SUPPORT 선별 지원 | 선별 지원 건 | 국내·해외 인건비 | 실행 시각 |
| 외부 실패 | LOGISTICS 물류 | 교체품 발송, 시료 회수, 재고 회수·교체 | 국내·해외 운송비 | 발생 시각 |
| 평가 | LAB_ANALYSIS 반품 분석 | 시험 항목 수 (`test_run`) | 시험 종류별 단가 29종 | 시험 종료 시각 |
| 평가 | ENGINEERING 엔지니어 공수 | 분석 수준별 시간 (L1 1h, L2 3h, L3 8h) | 시간당 인건비 | 원인 적용 시각 |
| 봉쇄 | CONTAINMENT_SORT / REWORK / SCRAP / RETURN_REPLACE | 봉쇄 조치 패널 수 | 패널당 선별·재베이킹 단가, 패널 원가 | 완료 시각 |

**규칙**
- **고객 측 손실 청구는 제조 원인(공정·자재·검사)이 적용된 반품에만** 잡는다. 불량 미재현·보류 건은 청구하지 않는다.
- **발견 단계 배수** (판매가 대비): 수입검사 1, 리플로 5, ICT·기능검사 10, 신뢰성 시험 15, 필드 50. 늦게 발견될수록 손실이 커지는 1:10:100 원리를 반영했다.
- **배상 상한** (반품 1건): 차량 3,000만, 반도체 1,500만, 산업 500만 원. 236건에 적용됐다.
- **실행 예정(미실행) 조치는 기록하지 않는다.** 기준 시점 이전에 실제로 생긴 비용만 기록한다.

## 기판 원가 (`product_cost`)
패널 원가 = 층당 8,000원 × 층수 × (HDI 1.6, 저손실 1.3, 후동 1.5) + 표면처리(ENIG 1만, ImSn 6천, OSP 3천 원)
기판 원가 = 패널 원가 ÷ 패널당 기판 수 ÷ 수율 0.95, 판매가 = 원가 × 1.30(차량) 또는 1.25

| 제품 | 패널 원가 | 기판 원가 | 판매가 |
|---|---:|---:|---:|
| 메모리 모듈 10층 | 90,000 | 15,789 | 19,737 |
| ADAS 레이더 8층 HDI | 143,120 | 9,416 | 12,241 |
| BMS 4층 후동 | 51,000 | 6,711 | 8,724 |
| 차량 ECU 6층 | 58,000 | 5,088 | 6,614 |
| SSD 기판 8층 HDI | 112,400 | 4,930 | 6,162 |
| 산업 제어 4층 | 38,000 | 4,000 | 5,000 |

## 추가된 것
| 종류 | 이름 | 내용 |
|---|---|---|
| 테이블 | `cost_rule` | 가정 단가 66개와 근거 |
| 테이블 | `product_cost` | 제품별 패널·기판 원가, 판매가, 계산식 |
| 테이블 | `loss_ledger` | 손실 원장 (분류, 항목, 반품·조사·고객·제품, 수량, 단가, 금액, 근거, 원천 레코드, 발생 시각) |
| 뷰 | `claim_loss` | 반품별 손실 합계와 항목별 금액 |
| 뷰 | `loss_by_month` | 월·항목별 손실 |
| 뷰 | `loss_by_investigation` | 조사(패턴)별 손실 |

테이블 42 → **45개**, 뷰 7 → **10개**

## 대시보드에서 쓰는 법
- **선택 기간 누적 손실:** `loss_ledger`에서 `occurred_at`이 기간 안인 `amount_krw` 합. 기준 시각 2025-12-31의 최근 30일은 약 42.6억 원
- **우선순위 점수의 손실 금액(30%):** `loss_by_investigation.total_krw`를 정규화
- **반품 상세 화면:** `claim_loss`, 또는 원장에서 그 반품의 행을 근거와 함께 표시

## 한계
- 모든 단가는 **가정**이다. 실제 현업 값이 아니며, 발표에서는 "가정 단가 기반 추정 손실"로 표기한다.
- 반품 수가 현실보다 많아서(연 1만 건) **연간 총액은 과대**하다. 건당·사건별 비교로 쓴다.
- 고객 측 손실 청구가 62%를 차지하므로, 발견 단계 배수와 배상 상한이 결과를 좌우한다. 2차 현업 메일에서 PCB 단가 수준과 배상 관행을 확인하면 근거를 보강할 수 있다.
