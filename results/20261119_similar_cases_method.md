# 유사 사례 검색 방식 변경 (2026-11-19, v4)

## 문제
WBS 5.2 정답셋에서 놓친 건을 보면, 원래 방식(데이터에 저장된 접수 문장 전체의 글자 유사도)이 증상과 상관없는 정형 문구에 끌려갔다. 예를 들어 인사말, 요청 문장, "라벨 훼손으로 Lot 번호 확인 불가" 같은 문구가 비슷하면 다른 증상의 사례가 위로 올라왔다.

## 비교 방법
- **정답:** 질의 시점에 원인이 확정된 과거 반품 중 같은 원인 + 같은 접수 증상
- **지표:** 상위 5건에 정답이 하나라도 있는 비율. 정답 후보가 있는 질의만 센다
- **순서:** 검증 기간(2025-08~09, 1,332건)에서 방식을 고르고, 평가 기간(2025-10~12, 1,819건)으로 확인하고, 정답셋 20건은 마지막에 확인만 했다

| 방식 | 검증 기간 | 평가 기간 |
|---|---:|---:|
| 원래 에이전트 (저장된 문장 유사도, 모자라면 같은 증상·같은 제품 최근 사례) | - | 85.5% |
| 문장 전체 유사도, 증상 구분 없이 | 84.0% | 77.3% |
| 증상 구절끼리 유사도 | 59.4% | 55.0% |
| 같은 증상 + 증상 구절 유사도 + 같은 제품 가산 | 92.9% | 91.1% |
| **같은 증상 + 문장 전체 유사도 (채택)** | **95.3%** | **92.0%** |

- 증상 구절만 비교하면 오히려 나빠진다. 구절이 짧고 템플릿이라 원인을 구분하지 못한다. 문장 전체에는 제품, 검출 단계, 고객 같은 사건 단서가 들어 있다. 문제는 다른 증상의 사례가 섞이는 것이었고, 같은 증상으로 먼저 거르면 해결된다.
- 정보 부족·분류 불가 접수는 증상을 몰라서 전체 과거 사례에서 문장 유사도로 찾는다.

## 정답셋 20건 (확인만)
| | 바꾸기 전 | 바꾼 뒤 |
|---|---:|---:|
| Hit@5 | 16 / 20 | **18 / 20** |

남은 2건은 이렇다.
- RMA-08022 (이물·오염·변색 / PSR 경화 부족): 이 원인에서 드문 증상이라 정답이 16건뿐이다.
- RMA-09283 (PSR 들뜸 / PSR 국부 밀착 불량, 단발): 같은 증상의 사건성 원인(PSR 경화 부족) 사례가 위를 차지한다.

## 기타
- 응답 시간: 호출당 평균 11ms (같은 증상 과거 사례만 계산, 문장별 글자 묶음은 캐시)
- SQLite와 PostgreSQL에서 테스트 61개 통과
- 데이터의 `similar_cases` 테이블(글자 유사도 기준선)은 에이전트가 더 이상 쓰지 않는다. 비교용으로 남겨 둔다.
